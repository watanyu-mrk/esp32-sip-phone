# PROJECT: ESP32-S3 SIP IP PHONE

## 1. บทบาทของ AI Agent

คุณคือ Senior Embedded Systems Engineer ผู้เชี่ยวชาญด้าน ESP32-S3, ESP-IDF, VoIP, SIP Protocol, RTP Audio Streaming, Digital Audio Processing, FreeRTOS และ Embedded Web Server

ภารกิจของคุณคือออกแบบและพัฒนาระบบ **SIP IP Phone บนบอร์ด XIAO ESP32-S3 Sense** ให้สามารถโทรเข้าและโทรออกผ่าน SIP Protocol ไปยัง IP PBX เช่น FreePBX หรือ Asterisk ได้จริง

ต้องพัฒนาเป็นระบบที่สามารถ Build, Flash, Debug และทดสอบการทำงานบนฮาร์ดแวร์จริงได้

## 2. Hardware Specification

บอร์ดหลัก:

- Board: Seeed Studio XIAO ESP32-S3 Sense
- MCU: ESP32-S3
- Flash: ตามสเปกของบอร์ด
- PSRAM: ตรวจสอบและเปิดใช้งานตามฮาร์ดแวร์จริง
- Wi-Fi: 2.4GHz
- Framework: ESP-IDF
- Language: C/C++

### 2.1 Audio Output (I2S)

กำหนด GPIO ดังนี้

```c
#define I2S_DOUT  7
#define I2S_BCLK  8
#define I2S_LRC   9
```

หน้าที่:
- ส่งเสียงจาก RTP Audio ไปยัง I2S Output
- รองรับเสียงสนทนาแบบ Real-time
- รองรับ Audio Buffer และ DMA
- ป้องกันเสียงสะดุดและเสียงขาดช่วง
- รองรับการปรับ Volume ผ่าน Web Configuration

หมายเหตุ: ต้องตรวจสอบการใช้งาน GPIO7, GPIO8 และ GPIO9 ร่วมกับวงจร microSD และห้ามเปิด SD SPI Driver มารบกวนการทำงานของ I2S

### 2.2 Audio Input (PDM Microphone)

ใช้ไมโครโฟน Digital PDM ที่ติดตั้งบน XIAO ESP32-S3 Sense

```c
#define PDM_DATA 41
#define PDM_CLK  42
```

หน้าที่:
- รับเสียงจากไมโครโฟน
- แปลง PDM เป็น PCM
- ส่งเสียง PCM ไปยัง RTP Encoder
- รองรับการสนทนาแบบ Full Duplex
- มีระบบปรับ Microphone Gain
- มีระบบ Noise Reduction ตามความเหมาะสม

ต้องตรวจสอบ I2S PDM RX Configuration ให้ตรงกับ ESP32-S3 และ ESP-IDF เวอร์ชันที่เลือก

### 2.3 Hardware Buttons

กำหนดปุ่ม 2 ปุ่ม

```c
#define BUTTON_ANSWER  3
#define BUTTON_HANGUP  2
```

การทำงาน:

**ปุ่ม ANSWER (GPIO3)**
- เมื่อมีสายเรียกเข้า กดเพื่อรับสาย
- เมื่อไม่มีสายเรียกเข้า สามารถใช้เป็นปุ่มโทรออกหรือเรียกหมายเลขที่ตั้งไว้ได้ตามการออกแบบ UI

**ปุ่ม HANGUP (GPIO2)**
- ขณะสนทนา กดเพื่อวางสาย
- ขณะกำลังโทรออก กดเพื่อยกเลิกการโทร
- ขณะมีสายเข้า กดเพื่อปฏิเสธสาย

ข้อกำหนด:
- รองรับ Debounce
- รองรับ Long Press ตามความเหมาะสม
- ตรวจสอบ GPIO3 ซึ่งเป็น Strapping Pin
- กำหนด Pull-up/Pull-down ให้เหมาะสมกับวงจรจริง
- ห้ามทำให้บอร์ดบูตไม่ขึ้นเมื่อกดปุ่มค้าง

## 3. SIP VoIP System

พัฒนาระบบ SIP Phone ที่รองรับมาตรฐาน SIP Protocol

### 3.1 SIP Registration

ต้องรองรับการลงทะเบียนกับ SIP Server โดยกำหนดค่าได้จาก Web Browser

ข้อมูลที่ต้องตั้งค่า:

- SIP Server IP / Domain
- SIP Server Port
- SIP Username
- SIP Password
- SIP Authentication Username
- SIP Display Name
- SIP Extension Number
- SIP Transport Protocol
- Registration Expiration
- STUN Server (Optional)
- Outbound Proxy (Optional)

ความสามารถ:
- Register SIP Account
- Unregister
- ตรวจสอบสถานะ Registration
- Auto Register เมื่อเปิดเครื่อง
- Auto Re-register เมื่อหมดอายุ
- Reconnect เมื่อ Wi-Fi หรือ SIP Server หลุด
- แสดง Error Code เมื่อ Registration ไม่สำเร็จ

### 3.2 SIP Protocol

ต้องรองรับ SIP Methods ที่จำเป็น:

- REGISTER
- INVITE
- ACK
- CANCEL
- BYE
- OPTIONS
- PRACK (ถ้าจำเป็น)
- INFO (ถ้าจำเป็น)
- REFER (Optional)

รองรับ:
- SIP UDP เป็นค่าเริ่มต้น
- SIP TCP เป็นตัวเลือก
- SIP Authentication ตาม RFC 3261 และ Digest Authentication
- Session Timer ตามความเหมาะสม
- DTMF RFC2833/RFC4733
- SIP Keepalive
- SIP Response Timeout
- Call State Management

ต้องเลือก SIP Stack ที่สามารถทำงานบน ESP32-S3 ได้จริง โดยตรวจสอบความเข้ากันได้กับ ESP-IDF ก่อนเลือกใช้งาน เช่น PJSIP หรือ SIP Stack ที่มีการรองรับ ESP32-S3 อย่างเหมาะสม

ห้ามสร้าง SIP Parser หรือ SIP Registration แบบจำลองเพื่อใช้แทน SIP Stack จริงโดยไม่มีเหตุผลทางเทคนิค

### 3.3 Call Function

รองรับการโทรดังนี้

**Outgoing Call**
1. ผู้ใช้สั่งโทรออก
2. ส่ง SIP INVITE
3. รอ SIP Response
4. รองรับ 100 Trying
5. รองรับ 180 Ringing
6. รองรับ 183 Session Progress
7. รองรับ 200 OK
8. ส่ง ACK
9. เริ่ม RTP Audio
10. สนทนาแบบ Two-way Audio
11. กดปุ่ม Hangup ส่ง BYE

**Incoming Call**
1. รับ SIP INVITE
2. ตรวจสอบข้อมูลผู้โทร
3. ส่ง SIP 180 Ringing
4. รอผู้ใช้กด Answer
5. ส่ง SIP 200 OK
6. รอ ACK
7. เริ่ม RTP Audio
8. สนทนาแบบ Two-way Audio
9. กด Hangup ส่ง BYE

รองรับกรณี:
- สายไม่ว่าง
- ปฏิเสธสาย
- ไม่มีผู้รับสาย
- Server ไม่ตอบสนอง
- Network Disconnect
- SIP Authentication Failed
- Call Timeout

## 4. RTP Audio System

ระบบเสียงเป็นส่วนสำคัญที่สุดของโครงการ ต้องออกแบบให้สามารถสนทนาได้จริง

### 4.1 Audio Architecture

ออกแบบระบบเสียงดังนี้

Microphone PDM
→ I2S PDM RX
→ PDM to PCM
→ Audio Processing
→ RTP Audio Encoder
→ RTP UDP
→ SIP Server / Remote Phone

ขารับเสียง:

RTP UDP
→ RTP Jitter Buffer
→ Audio Decoder
→ PCM
→ I2S TX
→ Audio Output

### 4.2 Audio Codec

รองรับ Codec ดังนี้:

1. G.711 A-law (PCMA)
2. G.711 μ-law (PCMU)

ให้ใช้ G.711 เป็น Codec หลัก เนื่องจากมีความเหมาะสมกับระบบ IP Phone และมีภาระการประมวลผลต่ำ

กำหนดค่าเริ่มต้น:
- Sample Rate: 8000 Hz
- Audio Channels: Mono
- Codec: PCMU หรือ PCMA
- RTP Payload Type: ตาม Codec Negotiation
- Packetization: 20 ms
- PCM: 16-bit

ต้องตรวจสอบ SIP SDP Negotiation ให้ตรงกับ Codec ที่อีกฝั่งรองรับ

### 4.3 Audio Processing

ต้องมี:
- RTP Jitter Buffer
- Packet Loss Handling
- Audio Buffer Management
- Audio Gain Control
- Microphone Gain
- Output Volume
- Noise Reduction
- Echo Cancellation (AEC) หากทรัพยากรและอุปกรณ์เสียงรองรับ

ห้ามออกแบบ Audio Task ให้ทำงานแบบ Blocking จนทำให้ SIP Task หรือ Network Task หยุดทำงาน

ต้องวิเคราะห์ Full Duplex Audio และปัญหาเสียงสะท้อนจากลำโพงกลับเข้าไมโครโฟน

หากต้องใช้ AEC ให้ประเมินความเหมาะสมของ ESP-SR หรือ DSP Library ที่รองรับ ESP32-S3 ก่อนนำมาใช้จริง

### FreeRTOS Task

ออกแบบ Task อย่างน้อยดังนี้:

1. SIP Task
2. RTP Receive Task
3. Audio Capture Task
4. Audio Playback Task
5. Button Task
6. Web Server Task
7. Wi-Fi Event Task
8. System Monitor Task

กำหนด Priority และ Stack Size ให้เหมาะสม

ห้ามใช้ Delay หรือ Blocking Operation ใน Task ที่มีผลต่อ Real-time Audio

ใช้ Queue, Event Group, Mutex และ Ring Buffer ตามความเหมาะสม

ต้องกำหนด Ownership ของ Audio Buffer และ SIP Session ให้ชัดเจน ป้องกัน Race Condition และ Memory Leak

## 8. FreePBX Compatibility

ระบบต้องสามารถทำงานร่วมกับ FreePBX / Asterisk ได้

ให้ทดสอบโดยใช้ SIP Extension ที่สร้างไว้ใน FreePBX

ตัวอย่าง Configuration สำหรับทดสอบ:

```text
SIP Server: 192.168.4.29
SIP Port: 5060
Transport: UDP
Extension: 101
Username: 101
Password: Configurable
Codec: PCMU / PCMA
RTP: UDP
```

ค่าดังกล่าวเป็นตัวอย่างสำหรับทดสอบเท่านั้น ต้องสามารถเปลี่ยนแปลงได้ผ่าน Web Browser

ต้องตรวจสอบ:
- PJSIP Endpoint Configuration
- Authentication
- AOR
- RTP Port
- Codec Compatibility
- SDP Negotiation
- NAT และ Firewall
- SIP Contact Registration

ต้องไม่สมมติว่า SIP Server ใช้ Port หรือ Codec แบบตายตัว

## 9. Security

คำนึงถึงความปลอดภัยของระบบ:

- ป้องกัน Web Configuration ด้วย Authentication
- ไม่เก็บ Password แบบ Plain Text ใน Log
- ใช้ NVS สำหรับ Configuration
- ป้องกัน Unauthorized SIP Calls
- จำกัดการเข้าถึง Web API
- รองรับ SIP TLS และ SRTP เป็นแนวทางเพิ่มเติม หาก Library และทรัพยากรรองรับ
- ตรวจสอบ Input จาก Web API
- ป้องกันการเปิดเผย SIP Credentials

## 11. Mandatory Rules for AI Agent
