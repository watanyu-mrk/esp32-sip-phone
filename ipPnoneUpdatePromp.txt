# PROJECT EXTENSION: ESP32 SIP IP PHONE WITH LVGL TOUCHSCREEN

## 1. Project Objective

ปัจจุบันโปรเจกต์ต้นฉบับ ESP32 SIP IP Phone สามารถทำงานได้สมบูรณ์ในส่วนของ SIP Communication ได้แก่

- SIP Registration
- SIP Incoming Call
- SIP Outgoing Call
- Answer Call
- Hangup Call
- RTP Audio Streaming
- Two-way Audio Communication
- Wi-Fi Connection
- Web Configuration
- Serial Terminal Logging

ให้พัฒนาต่อยอดโปรเจกต์เดิมเป็นรุ่นใหม่ที่มีหน้าจอสัมผัส โดยใช้ LVGL

**ชื่อโปรเจกต์ใหม่ต้องลงท้ายด้วย `_screen`**

ตัวอย่าง:

```text
Original Project:
esp32_sip_phone/

New Project:
esp32_sip_phone_screen/
```

## 2. New Hardware Specification

เปลี่ยน Hardware จาก XIAO ESP32-S3 Sense เป็น:

**Board: GUITION JC4827W543**

รายละเอียด:

- MCU: ESP32-S3
- Flash: 4MB
- PSRAM: 8MB (ตรวจสอบรุ่นย่อย)
- Display: 4.3 Inch
- Resolution: 480 x 272 Pixels
- Display Driver: ST3401A (ตรวจสอบ Revision และ Datasheet)
- Display Interface: ตรวจสอบจาก Schematic
- Touchscreen: ตรวจสอบว่าเป็น Capacitive หรือ Resistive
- Audio Amplifier: Onboard Speaker Amplifier
- Speaker: Onboard Speaker Circuit
- External Microphone: INMP441 I2S

Framework:

- ESP-IDF
- FreeRTOS
- LVGL
- C/C++

ให้เลือก LVGL Version ที่เข้ากันได้กับ ESP-IDF และ Display Driver ที่ใช้จริง

## 3. GPIO Configuration

มี Expansion IO จากบอร์ดจำนวน 4 ชุด

```text
Header 1: GPIO46, GPIO9, GPIO14, GPIO5
Header 2: GPIO6, GPIO7, GPIO15, GPIO16
Header 3: GND, 3.3V, GPIO17, GPIO18
Header 4: GND, 3.3V, GPIO17, GPIO18
```

หมายเหตุ: Header 3 และ Header 4 มี GPIO17/18 ซ้ำกันตามข้อมูลที่ได้รับ ให้ตรวจสอบ Schematic และตำแหน่ง Connector จริงก่อนใช้งาน

### 3.1 External Microphone: INMP441

ใช้ไมโครโฟน Digital I2S รุ่น INMP441

Pin Configuration เบื้องต้น:

```c
#define MIC_I2S_BCLK  GPIO_NUM_6
#define MIC_I2S_WS    GPIO_NUM_7
#define MIC_I2S_SD    GPIO_NUM_15
```

การเชื่อมต่อ:

| INMP441 | ESP32-S3 |
|---|---|
| VDD | 3.3V |
| GND | GND |
| SCK | GPIO6 |
| WS | GPIO7 |
| SD | GPIO15 |
| L/R | GND |

กำหนด L/R ลง GND เพื่อเลือก Left Channel

ข้อกำหนด:
- ใช้ I2S RX
- รองรับ 16-bit และ 24-bit PCM
- ตรวจสอบข้อมูลเสียงที่ส่งออกจาก INMP441
- รองรับการปรับ Microphone Gain
- รองรับ Full Duplex Audio
- แยก Audio Capture Task จาก UI Task
- ตรวจสอบ Audio Buffer และ DMA

ต้องตรวจสอบ GPIO6, GPIO7 และ GPIO15 ว่าเป็นขาที่สามารถใช้งานได้จริงตาม Schematic ของบอร์ด Revision ที่กำลังพัฒนา

ห้ามใช้ Pin Configuration ของบอร์ด XIAO ESP32-S3 Sense เดิมต่อไปโดยไม่ตรวจสอบ

### 3.2 Onboard Speaker

ใช้ภาคขยายเสียงที่ติดตั้งมาบนบอร์ด ไม่ต้องเพิ่ม Amplifier ภายนอก

ให้ตรวจสอบวงจร Onboard Speaker และ I2S Audio Output ก่อนเขียน Driver

หากบอร์ดใช้ NS4168 ให้ตรวจสอบ Pin Mapping จาก Schematic โดยมีข้อมูลอ้างอิงเบื้องต้นดังนี้:

```c
#define SPK_I2S_BCLK GPIO_NUM_42
#define SPK_I2S_LRC  GPIO_NUM_2
#define SPK_I2S_DOUT GPIO_NUM_41
```

ข้อกำหนด:
- ใช้ I2S TX
- ควบคุม Volume ได้
- รองรับ PCM Audio
- รองรับ G.711 PCMU/PCMA จาก SIP เดิม
- ตรวจสอบ Sample Rate และ Bit Width
- ตรวจสอบวงจรเปิด/ปิด Amplifier หากมี
- ห้ามกำหนด Pin ซ้ำกับ Display หรือ Touch

ต้องแยก Configuration ของ Microphone และ Speaker ออกจากกัน

หาก I2S Peripheral รองรับการทำงานร่วมกันแบบ Full Duplex ให้ประเมินก่อนใช้งาน หากไม่เหมาะสมให้แยก RX/TX Peripheral ตามความสามารถของ ESP32-S3

## 4. Display Driver and LVGL

พัฒนาระบบหน้าจอด้วย LVGL

ข้อกำหนด:

- Resolution 480x272
- Landscape Orientation
- Touchscreen Interface
- Responsive Layout
- Smooth UI Animation
- Anti-aliased Font
- Thai Font Support
- Icon Support

ต้องดำเนินการดังนี้:

1. ตรวจสอบ Display Controller ของบอร์ดจริง
2. ตรวจสอบ Datasheet และ Initialization Sequence
3. ตรวจสอบ Display Bus Interface
4. เลือก ESP-IDF Display Driver ที่รองรับ Controller
5. ทดสอบ Display ก่อนเริ่มพัฒนา UI
6. ทดสอบ Touchscreen
7. เชื่อมต่อ Display Driver เข้ากับ LVGL
8. สร้าง LVGL Display Flush Callback
9. กำหนด Draw Buffer ให้เหมาะสม
10. เปิดใช้งาน PSRAM เมื่อเหมาะสม

ห้ามสมมติว่า ST3401A ใช้ Driver หรือ Initialization Sequence เดียวกับ NV3041A

### LVGL Performance

- ใช้ Partial Rendering หรือ Direct Rendering ตามความเหมาะสม
- ใช้ DMA เมื่อ Driver รองรับ
- กำหนด LVGL Tick อย่างถูกต้อง
- กำหนด UI Task แยกจาก SIP/RTP Tasks
- ห้ามเรียก LVGL API จากหลาย Task โดยไม่มี Mutex
- ป้องกัน Display Flickering
- ป้องกัน Memory Fragmentation
- ลดการ Refresh หน้าจอโดยไม่จำเป็น

ต้องทดสอบ UI ต่อเนื่องโดยไม่กระทบ Audio Streaming

## 7. Touchscreen Support

ตรวจสอบ Touch Controller จากบอร์ดจริง

ต้องตรวจสอบว่าเป็น:
- Capacitive Touch เช่น GT911
- หรือ Resistive Touch เช่น XPT2046

ห้ามสมมติว่า Touch Controller ของทุกรุ่นย่อยเหมือนกัน

ข้อกำหนด:
- รองรับ Touch Coordinate
- รองรับ Touch Calibration หากจำเป็น
- รองรับ Screen Rotation
- รองรับ LVGL Input Device
- ป้องกันการกดซ้ำโดยไม่ตั้งใจ
- รองรับ Long Press
- ปุ่มต้องมีขนาดเหมาะสมสำหรับนิ้วมือ

หากใช้ GT911 ให้ตรวจสอบ I2C, INT และ RST Pin ตาม Schematic

หากใช้ XPT2046 ให้ตรวจสอบ SPI Bus และ Chip Select

### 8.1 Inter-module Communication

UI ต้องไม่เรียก SIP Stack โดยตรง

ให้สร้าง Application Event หรือ API Layer เป็นตัวกลาง

ตัวอย่าง Event:

```c
typedef enum {
    PHONE_EVENT_IDLE,
    PHONE_EVENT_REGISTERED,
    PHONE_EVENT_UNREGISTERED,
    PHONE_EVENT_INCOMING_CALL,
    PHONE_EVENT_OUTGOING_CALL,
    PHONE_EVENT_RINGING,
    PHONE_EVENT_CALL_CONNECTED,
    PHONE_EVENT_CALL_ENDED,
    PHONE_EVENT_CALL_FAILED,
    PHONE_EVENT_WIFI_CONNECTED,
    PHONE_EVENT_WIFI_DISCONNECTED
} phone_event_t;
```

เมื่อ SIP State เปลี่ยน ต้องแจ้ง UI ผ่าน Queue/Event System

UI จะรับ Event แล้วอัปเดตหน้าจอ

ห้ามให้ SIP Task เรียก LVGL API โดยตรง

ห้ามให้ LVGL Task ทำงานหนักจนขัดขวาง RTP Audio

## 12. Mandatory Development Rules

1. ห้ามแก้ไขโปรเจกต์ต้นฉบับ
2. ห้ามเขียน SIP Stack ใหม่
3. ห้ามทำให้ระบบโทรเข้าและโทรออกเดิมเสีย
4. ต้องตรวจสอบ Hardware Revision ก่อนเลือก Display Driver
5. ต้องตรวจสอบ Touch Controller ก่อนเลือก Touch Library
6. ต้องตรวจสอบ GPIO ทุกขาก่อนนำมาใช้
7. ต้องทดสอบ Audio Driver แยกจาก SIP
8. ต้อง Build ผ่านทุก Phase
9. ต้องใช้ LVGL จริง ไม่ใช่ Web UI แทนหน้าจอ
10. ต้องแยก UI Task จาก SIP/RTP Task
11. ห้ามให้ UI Refresh ทำให้เสียงสนทนาสะดุด
12. ต้องรักษา Web Configuration เดิม
13. ต้องรักษา Serial Logging เดิม
14. ต้องไม่ Mock การโทรเพื่ออ้างว่าระบบสมบูรณ์
15. หากทดสอบฮาร์ดแวร์จริงไม่ได้ ต้องระบุให้ชัดเจน
16. ต้องมี Git Commit แยกตาม Phase
17. ทุกการเปลี่ยนแปลงต้องมีผล Build/Test ประกอบ
